## Project

GymLog — a Flutter app for logging gym workouts and tracking weight progression/PRs. Backend is Firebase (Auth with Google + email/password, Cloud Firestore with offline persistence enabled). State management is `flutter_bloc`. Configured Firebase platforms: Android and iOS (`lib/firebase_options.dart` is generated by `flutterfire configure` — regenerate rather than hand-edit).

## Commands

```bash
flutter pub get                                   # install deps
flutter run                                       # run on connected device/emulator
flutter analyze                                   # lint (flutter_lints)
flutter test                                      # all tests
flutter test test/blocs/session_bloc_test.dart    # single file
flutter test --plain-name "substring of test name"   # single test by name
firebase deploy --only firestore                  # deploy firestore.rules + firestore.indexes.json
```

Tests live in `test/blocs/`, `test/utils/` and `test/widgets/`; bloc tests use `bloc_test` + `mocktail`, mocking repositories (e.g. `class MockSessionRepository extends Mock implements SessionRepository {}`). Firebase is never initialized in tests, so blocs must only touch Firestore through injected repositories.

## Architecture

**Layers:** `screens/` (UI) → `blocs/` (Bloc/Cubit, each with `part` files for events/states) → `repositories/` (Firestore/Auth access) → `models/` (Equatable value classes with `toMap`/`fromMap`/`copyWith`). Pure calculation helpers are in `utils/`.

**Dependency wiring (`lib/main.dart`):** repositories are provided app-wide via `MultiRepositoryProvider`. `AuthCubit` sits above everything; when authenticated, a second `MaterialApp` is built with user-scoped blocs (`ExerciseLibraryCubit`, `SessionHistoryCubit`, `SettingsCubit`, `SessionBloc`). The current user's uid is provided as a plain `String` via `RepositoryProvider.value`, so screens fetch it with `context.read<String>()`. Screen-local blocs (`ExerciseLoggerBloc`, `ExerciseDetailCubit`) are created in their screens with the repo + uid passed in.

**Firestore layout** (all data is per-user):
- `users/{uid}/exercises/{id}` — exercise library; seeded from `assets/exercises.json` on first sign-in (`ExerciseRepository.seedIfEmpty`, called from `AuthCubit`).
- `users/{uid}/sessions/{id}` — workout sessions with `status` of `'draft'` (in progress) or `'finished'`. At most one draft is expected; `SessionBloc` resumes an existing draft instead of creating another.
- `users/{uid}/sessions/{id}/exercises/{id}` — `SessionExercise` docs holding an embedded `sets` array of `SetEntry` maps, ordered by `orderIndex`. These docs also carry denormalized `uid`, `sessionStatus` and `sessionStartedAt` fields that are *not* on the `SessionExercise` model — `SessionRepository` writes them (`addExerciseToSession`, and `finishSession` flips `sessionStatus` on every exercise doc in the same batch). Keep them in sync if you add new ways to create or change sessions.

History/PR/ghost-set lookups (`getLastSessionSets`, `getAllSessionExercisesWithDates`) are one `collectionGroup('exercises')` query on `uid` + `exerciseId` + `sessionStatus == 'finished'`, ordered by `sessionStartedAt`. `firestore.rules` only permits that collection-group read when filtered by the caller's `uid`, and the composite index is in `firestore.indexes.json`. Data written before these fields existed is migrated by `backfillExerciseMetadata`, run in the background from `AuthCubit` and gated by an `exerciseMetaVersion` marker on `users/{uid}`. The collection-group name `exercises` is shared with the library collection.

**Weight model:** `SetEntry` stores both `weightInput` (what the user types: per side for barbell/smith, per dumbbell, stack weight, or added bodyweight load) and `weightTotal` (derived via `deriveTotal` in `utils/weight_calculator.dart`, using `barWeightKg` default 20). All stored weights are kg; `utils/unit_converter.dart` converts for display when `SettingsCubit.useLbs` is on (settings persist in `SharedPreferences`). PR/progression metrics (`utils/metrics_calculator.dart`) operate on `weightTotal`; estimated 1RM uses the Epley formula.

**Exercise logging flow:** `ExerciseLoggerBloc` loads the current sets, the last finished session's sets ("ghost sets", used to pre-fill), and full history in parallel; history is cached so PR flags are computed synchronously on each edit. Edits emit optimistically; weight/reps and notes are persisted on separate 600 ms debounce timers, structural changes (add/remove set, warmup/dropset toggles) persist immediately and cancel any pending sets debounce, and `close()` flushes pending writes. Warmup sets are excluded from PRs and progression everywhere (`workingSets` in `metrics_calculator.dart`). Background persist results are fed back through private `_PersistCompleted` / `_PersistFailed` events. The logger screen pushes updated sets back to `SessionBloc` via `SessionExerciseSetsUpdated` so the active-session view stays in sync.

**Session rules:** max 10 exercises per session (enforced in `SessionBloc`); discarding/deleting a session batch-deletes its exercise sub-docs in chunks of 500. `SessionBloc` only manages the active draft — deleting finished sessions goes through `SessionHistoryCubit.deleteSession`. On a failed write `SessionBloc` emits `SessionError` and then restores the previous `SessionActive`, so UI listeners show the error while builders skip it.

**UI / theming:** all styling comes from `lib/theme/app_theme.dart` — `AppTheme.dark` (primary design) / `AppTheme.light`, plus a `GymColors` theme extension (`GymColors.of(context)`) for the brand accent and colors ColorScheme lacks (PR gold, warmup, dropset, per-muscle-group). Use `AppTheme.number()` for numerals. Fonts (Barlow / Barlow Condensed) are bundled in `assets/fonts/`, not fetched. Theme mode is a user setting in `SettingsCubit`, which is provided above auth so it applies to login too. Signed-in root is `AppShell` (bottom nav: Today / History / Exercises / Profile); shared building blocks live in `lib/widgets/` (`StatTile`, `SessionCard`, `SetBadge`, `MuscleAvatar`, `SectionHeader`, `EmptyState`) and formatting helpers in `lib/utils/formatters.dart`.
